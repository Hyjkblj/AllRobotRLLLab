# 外部运行时接入说明

平台进程只负责编排、状态机、对象存储和队列；GMR、GVHMR、Isaac Lab 和 MuJoCo 运行时在各自的 Python/CUDA 或 C++ 环境中运行。运行器之间只通过文件产物、JSON manifest 和 SHA-256 交换数据。机器人、任务和 provider 由 `ROBOT_ADAPTER_MODULES` 与 `RobotSpec` 选择。

## 环境边界

| 运行时 | 必要环境 | 平台配置 |
| --- | --- | --- |
| GMR | Python 3.10、MuJoCo、Mink、SMPL-X | `GMR_PATH`、`GMR_PYTHON` |
| GVHMR | Python 3.10、Torch 2.3/cu121、checkpoint | `GVHMR_PATH`、`GVHMR_PYTHON` |
| Isaac Lab/RSL-RL | Isaac Sim 5.1、Isaac Lab 2.3、Torch 2.7/cu128 | `ISAACLAB_PATH`、`ISAACSIM_PATH`、`ISAAC_PYTHON` |
| Unitree RL Lab | 安装在 Isaac Lab 环境中的 `unitree_rl_lab` | `UNITREE_RL_LAB_PATH` |
| Unitree MuJoCo | MuJoCo 3.3.6、`unitree_sdk2`、G1 controller | `UNITREE_MUJOCO_PATH`、`SIM2SIM_PYTHON` |

每个启用的 RobotSpec 都必须提供与其 joint/body 顺序一致的模型资产。G1 使用 `G1_MJCF_PATH`，H1 使用 `H1_MJCF_PATH`，其他 adapter 应在自己的 `asset_env` 中声明变量。生产环境缺失任一已启用机器人的模型时，动作编译会被拒绝，不会退回根位姿复制。

运行时要求按进程 profile 统一管理：`api` 不要求外部运行时，`motion-cpu` 检查所有已注册 RobotSpec 的模型，`motion-gpu` 要求 GMR/GVHMR，`isaac-gpu` 要求 Isaac Lab/Isaac Sim/Unitree RL Lab，`native-isaac-gpu` 只要求 Isaac Lab/Isaac Sim，`sim2sim-gpu` 要求对应 MuJoCo runner；staging 的 GPU worker 使用 `gpu` profile（上述运行时全部要求）。Settings、runtime doctor、manifest 和外部检查脚本共享这套定义。

staging/production 还必须运行单实例 `outbox-dispatcher`（`python -m backend.app.workers.outbox_worker`）。它从 PostgreSQL 事务 outbox 领取事件并投递到 Redis/Celery；同一批事件使用行锁和幂等键，API/worker 重启不会丢失。API、CPU worker 和 GPU worker 必须挂载同一个 `.runtime` 卷，以共享 RewardConfig 的不可变 JSON 版本索引；生产环境缺少被 Run Manifest 引用的 reward SHA 时，训练会 fail closed。

训练、导出和 sim2sim 外部进程运行期间，worker 在 `.runtime/runs/<run_id>/external-process.json` 写入子进程 PID、阶段和命令。`POST /runs/{run_id}/cancel` 会先保留 Run 的取消审计，再尝试终止该子进程组；取消 outbox 任务会重复执行同一操作，因此 API 或 worker 暂时重启都不会让已取消作业继续占用 GPU。进程正常退出或超时后 marker 会被原子清理，恢复扫描同时检查该 marker，避免把仍在运行的外部作业误判为 worker 丢失。

启用 G1 与 H1 的示例：

```bash
export ROBOT_ADAPTER_MODULES=adapters.unitree_g1_29dof,adapters.unitree_h1_19dof
export G1_MJCF_PATH=/opt/GMR/assets/unitree_g1/g1_mocap_29dof.xml
export H1_MJCF_PATH=/opt/assets/unitree_h1/h1.xml
export H1_SIM2SIM_COMMAND='python /opt/h1_sim/evaluate.py --seed {seed} --policy {policy} --output {output}'
```

G1 的 `unitree_rl_lab` provider 只支持 `g1_mimic`。H1 的 `h1_mimic` 使用 `native_isaac_lab` provider 和 `H1_SIM2SIM_COMMAND`；若 provider、任务或 sim2sim adapter 不匹配，API 入队和 worker 执行都会拒绝该 Run。

## 注册与检查

初始化运行目录：

```powershell
python tools/robotlab.py init --mode local_file
```

注册外部 checkout（示例）：

```powershell
python tools/robotlab.py runtime register gmr --path D:/runtime/GMR --python D:/envs/gmr/python.exe --revision bb1bbe4
python tools/robotlab.py runtime register gvhmr --path D:/runtime/GVHMR --python D:/envs/gvhmr/python.exe --revision 6ec3ca3
python tools/robotlab.py runtime register isaac_lab --path D:/runtime/IsaacLab --python D:/envs/isaaclab/python.exe --revision 3c6e67bb5
python tools/robotlab.py runtime register unitree_mujoco --path D:/runtime/unitree_mujoco --revision ae6a840
python tools/robotlab.py runtime doctor --runtime-dir runtime
```

当第三方目录是当前项目 `third_party` 下的源码快照、没有独立 `.git` 时，省略 `--revision` 会自动记录目录内容哈希 `content:<sha256>`，之后目录内容发生变化会被标记为 `NOT_READY`。生产建议使用独立 checkout 并锁定上游 commit。

API 侧同样提供：

```text
GET /api/v1/runtime/doctor
GET /api/v1/runtime/doctor?profile=gpu
```

## 业务链路

1. 上传动作或视频，API 在对象存储中写入版本并由 `asset-io` worker 校验 SHA-256。
2. `motion-cpu` worker 对所选机器人轨迹直接读取；对视频依次调用 GVHMR 和 GMR，生成 `retarget_motion.pkl/npz`。
3. `MuJoCoKinematicsCompiler` 对每帧设置 qpos/qvel，调用 `mj_forward` 生成 `body_pos_w`、`body_quat_w`、线速度和角速度，发布 `TrainMotionNPZ`。
4. `isaac-gpu` 或 `native-isaac-gpu` worker 调用任务声明的训练 provider，持久化 checkpoint、指标和运行 manifest。
5. 导出阶段调用 Isaac/Unitree 导出命令并生成策略包；`sim2sim-gpu` 对三个不同 seed 调用 Unitree MuJoCo，收集视频、曲线、控制参数和 metrics。
6. 只有三个 seed 均通过阈值、产物 checksum 和 manifest 校验，运行才会进入 `READY_TO_DOWNLOAD`。

## 生产验收

环境检查通过不代表训练成功。服务器验收至少需要：

```powershell
python scripts/collect_runtime_manifest.py --root . --strict
python scripts/check_external_runtime.py --json
python tools/robotlab.py runtime doctor --runtime-dir runtime
```

需要检查指定 profile 时显式传入，例如 GPU worker：

```bash
python scripts/check_external_runtime.py --profile gpu --json
python scripts/collect_runtime_manifest.py --profile gpu --strict --output .runtime/runtime-manifest.json
python tools/robotlab.py runtime doctor --profile gpu --runtime-dir runtime
```

随后用真实视频或已启用机器人的动作完成一次上传、GVHMR/GMR、MuJoCo 编译、对应 Isaac train/play/export 和三 seed sim2sim。任何 `RUNTIME_*`、`KINEMATICS_*`、`ISAAC_*` 或 `SIM2SIM_*` 错误都应在对应阶段失败并保留日志，而不是降级到 fake smoke。
