# P0 契约与 G1 适配器实现说明

本分支 `codex/p0-contracts-g1-adapter` 对应方案中的 P0 第一批交付：版本化数据契约、G1 29 DoF 资产自检、直接动作内容识别、奖励白名单、配置生成和只读 FastAPI API。现有 `frontend-prototype` 保持为原型，不作为生产 API 的依赖。

## 分层边界

```text
apps/api                 ASGI 入口
backend/app/api          DTO、请求 ID、HTTP 错误
backend/app/application  奖励目录、配置生成、manifest 冻结
backend/app/domain       Pydantic 契约、状态机、端口（无框架/仿真依赖）
backend/app/adapters     动作格式识别、G1 XML/URDF 适配器
backend/app/workers       安全命令执行和阶段幂等键
adapters/unitree_g1_29dof  G1 资产、29 个关节和控制参数
```

API 层没有训练、Isaac、Celery、数据库或对象存储副作用。`StageRunner` 使用参数数组、固定工作目录和 `shell=False`，供后续 Celery worker 编排。

## 本地验证

使用已存在的 Conda 环境：

```powershell
conda activate allrobotrl-platform
python -m pytest -q
python -m compileall -q backend adapters apps
uvicorn apps.api.main:app --reload
```

只读接口前缀为 `/api/v1`，包括 `/health`、`/robots`、`/robots/{id}/self-check`、`/reward-templates`、`/training-config/schema` 和 `/motions/detect`。动作检测只读取配置的 `MOTION_ASSET_ROOT`，普通上传的 pickle 默认拒绝。

## 当前边界

本次不宣称 Isaac Lab 训练、PostgreSQL/Redis/MinIO、Celery、JIT/ONNX 导出或三种子 sim2sim 已完成；这些按方案的 P2/P3 继续接入。未采集的运行时身份保持 `pending`，不会写入伪造版本或发布 hash。
