# P3 实现说明

P3 在 P2 Run/Attempt 闭环上增加了训练、策略导出、三种子 sim2sim 验收和产物下载索引。当前实现提供可重复的 CPU smoke backend，用于验证平台编排、契约、文件校验和对象存储边界；它不代表已经在 Isaac Lab/Isaac Sim 或 Unitree MuJoCo 上完成真实 GPU 训练。

## 已交付能力

- `POST /api/v1/runs/{run_id}/train`：校验 `TrainingConfig`，生成确定性的 checkpoint JSON 和结构化训练指标。
- `POST /api/v1/runs/{run_id}/export`：生成 TorchScript/JIT 与 ONNX，执行 CPU smoke inference，并构建 `policy_bundle.tar.gz`。
- `POST /api/v1/runs/{run_id}/sim2sim`：固定三个不同 seed，按生存率、关节 RMSE、根位置 RMSE、姿态误差、饱和率、足滑和 seed spread 阈值聚合报告。
- `GET /api/v1/runs/{run_id}/sim2sim`：读取验收报告。
- `GET /api/v1/runs/{run_id}/artifacts`：按项目权限列出 checkpoint、策略包和 sim2sim 报告产物。
- `GET /api/v1/artifacts/{artifact_id}`：返回权限检查后的下载 URL。

长任务执行模式：默认 `sync_smoke` 仅用于本地契约测试；设置 `EXECUTION_MODE=async` 或请求头 `X-Execution-Mode: async` 后，训练、导出和 sim2sim 接口只做校验并返回 HTTP `202` 的 `TaskSubmission`，任务进入 `isaac-gpu` 或 `sim2sim-gpu` 队列。Celery worker 使用 `backend.app.workers.p3_tasks.register_p3_tasks` 注册稳定任务名 `allrobotrl.p3.train`、`allrobotrl.p3.export` 和 `allrobotrl.p3.sim2sim`，消费后调用同一 `TrainingService` 应用服务。

PostgreSQL 模式由 `DATABASE_URL` 启用，API/worker 会使用同一套持久化 UoW；启动前执行全部 migration：

```powershell
conda run -n allrobotrl-platform python -c "import os; from pathlib import Path; from backend.app.infrastructure.postgres import PostgresDatabase; PostgresDatabase(os.environ['DATABASE_URL']).apply_migrations(Path('infra/migrations'))"
celery -A backend.app.workers.celery_app:celery_app worker -Q isaac-gpu,sim2sim-gpu --loglevel=INFO
```

PostgreSQL 将外部用户标识映射到 `users.external_id`，Run 幂等键存储在 `run_idempotency`，不会要求 API 的 `X-User-Id` 必须是 UUID。

策略包包含：

```text
policy.pt
policy.onnx
export_meta.json
params/deploy.yaml
params/env.yaml
params/agent.yaml
params/normalization.json
params/action_scale.json
manifest/run_manifest.json
manifest/manifest.sha256
sim2sim_report.json
checksums.sha256
```

`checksums.sha256` 不包含自身，但会列出包内其它每个文件；构建完成后服务会立即重新计算并验证清单。对象存储 key 使用 `projects/{project_id}/runs/{run_id}/attempts/{attempt_id}/artifacts/{kind}/{filename}`，禁止路径穿越。

## 本地基础设施

Docker Desktop 启动后运行：

```powershell
docker compose -f infra/compose/docker-compose.p2.yml up -d
```

为避免与主机上已有服务冲突，端口为：PostgreSQL `5434`、Redis `6381`、MinIO API `9000`、MinIO Console `9001`。`minio-init` 会创建 `allrobotrl` bucket。

启动 API 前设置：

```powershell
$env:DATABASE_URL = "postgresql://allrobotrl:allrobotrl_dev_only@127.0.0.1:5434/allrobotrl"
$env:REDIS_URL = "redis://127.0.0.1:6381/0"
$env:MINIO_ENDPOINT = "127.0.0.1:9000"
$env:MINIO_ACCESS_KEY = "allrobotrl"
$env:MINIO_SECRET_KEY = "allrobotrl_dev_only"
$env:MINIO_BUCKET = "allrobotrl"
$env:MINIO_SECURE = "false"
uvicorn apps.api.main:app --reload
```

验证基础设施：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health/infrastructure
```

## 运行 smoke 闭环

```powershell
conda activate allrobotrl-platform
python -m pytest -q
```

`p3_run_states`（迁移 004）会持久化训练配置、checkpoint、导出元数据、策略包和 sim2sim 报告；Celery worker 使用 late acknowledgement 和 worker-lost redelivery，并通过共享运行卷恢复中间文件。真实 Isaac Lab v2.3.0/Isaac Sim 5.1.0 训练 worker、真实 Unitree MuJoCo sim2sim adapter、GPU lease 和生产指标明细仍是后续服务器接入项。生产发布不得将 `fake_smoke` 结果标记为真实策略验收。

staging/production 必须设置 `P3_BACKEND` 为真实运行时适配器标识（当前预留 `isaac_lab`），平台拒绝 `fake_smoke` 配置，并在真实 adapter 注册前拒绝执行任何 P3 任务；这样服务器可以先验收 API、迁移、队列、重试和权限链路，而不会把 CPU smoke 误发布为生产策略。GPU worker 通过 Compose `gpu` profile 启动，并把 Isaac/GMR/GVHMR/Unitree 目录以只读 volume 挂载。
