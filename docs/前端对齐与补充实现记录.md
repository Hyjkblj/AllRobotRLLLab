# 前端对齐与补充实现记录

基于以下文档进行对齐：

- 《人形机器人RL平台本次对话总结》
- 《通用人形机器人RL训练平台开发PRD-v0.3》
- 《G1人形机器人RL训练平台完整闭环技术方案》

## 一、对齐结论

当前前端已经具备本地 React 工作台和真实 MuJoCo 动作编辑原型，但此前只覆盖了“项目/资源、动作检测、奖励权重、训练提交、SSE 日志”的骨架，尚未形成可验收的完整闭环。

本次在 `codex/frontend-alignment` 分支补齐了平台工作台的用户路径和关键状态表达：

```text
项目与资源 → 动作流水线 → 训练监控 → sim2sim 验收 → 策略包
```

## 二、发现的问题

### 业务逻辑

1. 原导航只有四个入口，训练、验收和策略包混在同一页，用户无法判断下一步操作。
2. 训练页只能提交训练和导出，缺少取消、失败重试、attempt 语义和断线恢复的可见反馈。
3. Reward Builder 只有开关和权重，未暴露注册参数、单位/来源、退火策略，也没有明确安全终止项不可关闭。
4. 没有 sim2sim 报告页面，无法查看三种子指标、硬阈值和失败归因。
5. 没有策略包页面，产物、校验和、下载权限和“不可直接用于真实机器人”提示不可见。
6. 动作流水线的 GVHMR/GMR 尚未接入真实 GPU worker，原页面没有说明当前能力边界和后续回退路径。

### 用户体验

1. 缺少全局阶段进度，用户在项目、动作、训练之间跳转时没有上下文。
2. 训练事件只有一列日志，没有总回报、跌倒率、显存等关键指标摘要。
3. 失败状态只有红色标签，没有动作/奖励/模型控制/运行时的诊断建议。
4. 报告和产物缺少空状态、加载状态、错误恢复入口。
5. 部分图标按钮没有显式 `aria-label`，移动端新增导航后需要控制触摸目标和横向溢出。

### UI 风格与样式

1. 原有银白工作台风格和新增平台页面之间缺少统一的阶段、指标和结果组件。
2. 奖励项参数信息层级不足，权重输入和参数输入没有明确标签。
3. 表格/列表在窄屏下容易挤压，缺少可读的报告卡片和安全提示样式。
4. 缺少 reduced-motion 处理，异步任务状态也没有统一的 loading/disabled 反馈。

## 三、本次补充实现

### 已完成

- 新增五阶段 `WorkflowStrip`：资源、动作、训练、验收、策略包，可从任意阶段回退。
- 扩展平台导航：训练监控、验收报告、策略包独立入口。
- Reward Builder 支持注册参数编辑、单位/来源展示、线性/Cosine 退火选择，并锁定平台安全终止项。
- 训练监控增加总回报、跌倒率、GPU 显存指标卡；SSE 事件按级别展示并保留游标提示。
- 增加训练 Run 的取消与失败/取消后的新 attempt 重试入口。
- 新增 sim2sim 报告页：三种子卡片、通过阈值、硬失败列表和动作/奖励/模型控制回退入口。
- 新增策略包页：产物清单、SHA-256、大小、下载接口和安全提示。
- 为动作流水线增加当前 runner 能力边界说明，避免把未接入的 GVHMR/GMR 标记为已完成。
- 增加移动端布局、触摸尺寸、空状态、错误状态和 `prefers-reduced-motion` 样式。
- 扩展 `platformClient`：`getSim2simReport`、`getArtifact`。
- 新增 `docs/前端对齐与补充实现记录.md` 作为本轮评审基线。

### 本轮新增的前后端闭环

- 新增 `POST /api/v1/motions/{asset_version_id}/process` 和两个 pipeline 查询接口，支持异步队列或 `sync_smoke` 本地执行。
- 新增可持久化的动作流水线记录：检测、G1 直通 retarget、编辑质量门、TrainMotionNPZ 编译、发布五个阶段均保存状态、耗时、错误码和输出资产版本。
- Local File worker 现在会先派发 outbox，再处理 `assets.validate`、`assets.uploading`、`runs.created`、`runs.retry` 和动作处理任务；上传后的 NPZ/CSV/PT 会被真实读取、校验并注册为 READY 资源。
- 训练提交在存在资产记录时只接受 READY 的 TrainMotionNPZ；取消后的 Run 可以创建新 attempt，并携带原训练配置自动重试。
- 前端动作页已从单次 detector 调用升级为提交/轮询 pipeline，训练动作下拉列表仅展示 READY 的 TrainMotionNPZ，并呈现质量门和失败码。

### 仍需后端/运行时补齐

- 真实 GVHMR/GMR runner、MuJoCo body kinematics compiler 及其阶段事件和产物 API（当前已有 NPZ/CSV/PT 的 CPU 直通转换）。
- Isaac Lab/RSL-RL 训练、play/export 和 GPU lease 的真实 worker 证据。
- Unitree MuJoCo 三种子评估视频、曲线和真实 adapter 版本信息。
- 项目角色、人工复核和短时下载地址在生产鉴权中的完整联动。
- Playwright 主流程覆盖和目标 Linux/WSL2 GPU 环境验收。

这些能力未在前端伪造；页面会根据 API 返回的状态、404 和错误码显示可恢复的下一步。
