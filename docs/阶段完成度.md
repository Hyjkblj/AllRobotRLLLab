## Local File Mode 基线

默认开发运行模式已切换为 `local_file`。`runtime/` 下保存项目和资源元数据、每个 Run 的 `manifest.json`、原子 `state.json`、追加 `events.jsonl`/`metrics.jsonl`、内容寻址产物和本地幂等任务队列；`LocalFileUnitOfWork` 与 PostgreSQL UoW 共享同一 application/domain ports。`robotlab init/start/status/stop/doctor --mode local_file` 可在没有 Docker 或数据库的 WSL2/Linux 环境启动和检查本地 API，并启动持久化本地 worker。GPU lease 与 Run 恢复扫描已提供基础实现，真实 Isaac/RSL-RL worker 仍需按 D 阶段在目标 GPU 环境接入。

## 部署前置更新

- 阶段 0 运维入口已加入 `robotlab` CLI：`doctor`、`init`、`start`、`stop`、`status`、`run`、`logs`、`artifact`。CLI 只检查和调用 Docker/Compose/API，不会自动安装或修改系统组件。
- staging Compose 已增加一次性 `migrate` 服务。迁移使用 PostgreSQL advisory lock 和 `schema_migrations` 表，既支持新库初始化，也支持已有持久化卷的增量迁移。
- staging 的 `worker-cpu` 只消费 `cpu` 队列；`worker-gpu` 使用 `gpu` profile、`gpus: all` 和外部只读运行时挂载，消费 `isaac-gpu,sim2sim-gpu`。
- staging/production 的 API 会要求 PostgreSQL、Redis、MinIO、`WORKER_AUTH_TOKEN` 和非 `fake_smoke` 的 `P3_BACKEND`，内部 worker 写接口同时校验 `X-Worker-Id` 与 `X-Worker-Token`。
- train/export/sim2sim 的 API 入队、同步执行和 worker 消费均按 Run 的 `robot_id + task_id` 校验 provider/adapter 支持；错误的跨机器人 provider 组合会在执行前 fail-closed。
- `default_task_registry()` 不再隐式生成 G1 任务；旧调用必须显式使用 `legacy_g1_task_registry()`，避免通用服务因缺少 registry 而绑定 G1。
- `scripts/collect_runtime_manifest.py` 记录仓库 SHA、外部运行时 Git SHA、Python/包版本、GPU 信息和 G1 MJCF/URDF/USD 文件 hash；第三方源码、权重和 checkpoint 仍不进入 Git。

上述内容使平台可以安全上传服务器进行部署验收和队列/持久化实测，但不会伪造真实 Isaac Lab/RSL-RL 或 Unitree MuJoCo 通过结果。真实训练 adapter、GPU lease 和物理验收仍需在目标服务器接入并提供运行证据。

## 本轮新增

- `POST /api/v1/runs/{id}/train|export|sim2sim` 支持 `X-Execution-Mode: async`，返回 HTTP `202` 和 `TaskSubmission`。
- `P3DispatchService` 负责任务校验、队列选择和 SHA-256 幂等键。
- `P3TaskExecutor` 与稳定 Celery task names：`allrobotrl.p3.train`、`allrobotrl.p3.export`、`allrobotrl.p3.sim2sim`；`backend.app.workers.celery_app` 提供可直接启动的 worker entrypoint。
- PostgreSQL UoW 已支持 project/member、Run/Attempt、SSE event、audit、outbox、asset/version 和 artifact 元数据；`users.external_id` 映射外部身份，`run_idempotency` 持久化幂等键。
- 默认 `sync_smoke` 仍用于本地契约测试；生产异步模式必须接入 Redis/Celery 和持久化 repository。
- 前端 Platform Workbench 使用 `/api/v1`，MuJoCo 编辑器使用 `/api/mujoco`；Vite 已按路径分流，Local File Mode 提供 `/api/v1/uploads/*` 与 `/api/v1/objects/*` 浏览器上传/下载适配。
- `infra/migrations/004_p3_run_state.sql` 持久化跨进程恢复所需的 P3 状态；API/worker 共享运行卷，Celery 配置 late acknowledgement 和 worker lost redelivery。
